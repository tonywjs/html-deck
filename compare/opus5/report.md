# Claude Opus 5 자기 보고

**1. 산출물**
- `deck.html` 190,970 bytes (자체완결, 엔진과 런타임 인라인, 플레이스홀더 잔여 0)
- 소스 `deck-src.html` 38,286 bytes

**2. 규모**
- 6슬라이드. 슬라이드당 최대 장면 4개(2번과 5번)
- 노드 52개(6/9/5/11/8/13), 엣지 7개(4번 4, 5번 1, 6번 2)

**3. 정적 검사**
- `pass: true`, 오류 0, 경고 0. 제목 교체("html-deck 장면 연출 가이드"), 줄표 0, fx 대상 모두 해석됨, 장면 번호 연속, `.fig-elabel{font-size:14px}` 포함, 14px 미만 선언 없음
- 브라우저 검증은 규칙에 따라 미수행. 대신 채움(콘텐츠 74~79%, 2200 여정 75%)과 글자 하한을 손으로 계산해 확인

**4. 사용 기능**
- fx 다섯 종 전부: focus 3, view 3, flow 4, pulse 6, reset 4
- 전환 프리셋 5종: rise(1, 5번), fade(2번), zoom-in(3번), flow(4번), zoom-out(6번)
- 여정 캔버스: 6번 `2200x720`, 장면 0 view로 시작해 전체 줌아웃, 오른쪽 팬
- data-step: 단일과 범위(`2-3`, `2-4`) 모두, 대비용으로 `data-flow="on"` 상시 화살표도 사용
- 각 슬라이드가 자기 주제를 실제로 시연: 2번은 실제로 단계 공개(범위 요소가 나타났다 사라짐), 3번은 실제로 줌인과 딤, 4번은 화살표가 흐르고 노드가 강조되고 reset으로 멈춤, 5번은 편집 모드와 타임라인, 6번은 넓은 캔버스를 팬

**5. 어려웠던 점**
- 장면 번호 연속성: 범위 `n-m`은 양 끝만 등록되므로 사이 번호를 단일 요소로 메워야 했다.
- 카메라 축소 아래 글자 하한: 2200 캔버스가 약 0.58배로 실려 모든 글자를 26px 이상으로 잡아야 14px 기준을 넘었다.
- 브라우저 없이 자기 시연과 배치를 동시에 만족시키려 모든 노드의 bbox를 손으로 계산했다.
